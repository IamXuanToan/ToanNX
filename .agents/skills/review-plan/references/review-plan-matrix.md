# Ma trận Kiểm toán Plan 12 Trục (`review-plan`)

Dùng bảng này khi thẩm định mọi file trong `docs/plans/` (cấu trúc `<YYYY>/<MM>/<DD>/`). Chỉ báo lỗi có bằng chứng từ plan, rule/tài liệu và source thật; mục nào không thuộc phạm vi plan thì bỏ qua trong báo cáo.

| # | Trục thẩm định | Nguồn đối chiếu bắt buộc | Điểm soi kỹ & "Bẫy" kinh điển trong repo ToanNX |
| --- | --- | --- | --- |
| 1 | **Fact-check Codebase & Dependency** | `backend/app/`, `frontend/src/modules/`, `pyproject.toml`, `package.json`, `docs/plans/` | • Plan gọi tên service/method/model không tồn tại hoặc đã bị thay thế (ví dụ lấy từ plan cũ đã deprecated).<br>• Sai đường dẫn thư mục, sai phiên bản thư viện trong `package.json`/`pyproject.toml`.<br>• Tự ý đưa gói ngoài vào thiết kế mà không tách bảng **Dependency mới chờ duyệt** (`docs/rules/common.md` §2, §5). |
| 2 | **Tái sử dụng Common & Phạm vi** | `docs/common-catalog.md`, `backend/app/core/`, `frontend/src/shares/` | • Tự vẽ upload riêng thay `AttachmentPicker`/`AttachmentService`.<br>• Tự chế bảng/filter/form/editor/mã hóa riêng thay `DataTable`, `FilterSelect`, `SelectField`, `FormPage`, `TiptapEditor`, `SecretCipher`, `CacheService`, `useTableState`, `useTabState`, `useBulkActions`.<br>• Đề xuất tính năng/module ngoài yêu cầu hoặc bảng cấu hình module runtime (`SYSTEM_CONTEXT.md`). |
| 3 | **Kiến trúc & Dữ liệu Backend** | `docs/rules/backend.md`, `db-migration`, `backend/app/core/` | • Sai tầng `url → view → service → repository → ORM`; task/cron/webhook gọi ORM/repository trực tiếp; service dùng `@staticmethod` công khai hoặc tạo `XxxService()` trong method.<br>• Tạo lớp view/service nền mới thay `CoreModelViewSet`/`CoreApiView`/`CoreCrudService`/`CoreRepository`.<br>• **Bẫy `OneToOneField` + Soft Delete**: model kế thừa `CoreModel` (có `deleted_at`) mà dùng `OneToOneField` hoặc `unique=True` ngắn sẽ chặn tạo lại sau khi xóa mềm; phải dùng `ForeignKey` + `UniqueConstraint(condition=Q(deleted_at__isnull=True))`.<br>• Thiếu `JournalTracker` trước `CoreModel`, thiếu partial index cho `owner_field`, dùng `FloatField` thay `DecimalField`, thiếu `help_text`/`verbose_name`/`db_comment`.<br>• Quên `action_permissions` (kể cả `"create": DENY` cho ViewSet chỉ đọc có bulk POST), `bulk_delete_enabled`, `bulk_update_serializer_class` cho cờ boolean, `Core*InFilter`, `action_rate_limits` trong `settings.RATE_LIMITS`. |
| 4 | **Kiến trúc, UI & Token Frontend** | `docs/rules/frontend.md`, `.agents/rules/21-frontend-ui.md`, `frontend/src/app/globals.css` | • Gọi API ngầm trong Server Component (`serverApiGet`/`backendFetch`) — vi phạm luật **100% Client-side React Query + `signal`**.<br>• View gọi `useQuery`/`useState`/`useEffect`/`useRouter`; gộp hook trong `.tsx`; đặt file trong `views/hooks/` hoặc nhóm `shared`/`common` trong module; gộp nhiều model vào 1 service.<br>• **Bẫy màu Tailwind**: dùng `bg-amber-500`, `text-purple-600`, `bg-sky-500` hoặc hex trực tiếp trong component khi `globals.css` chưa khai token `--color-*` (`theme-tokens.test.ts` fail!).<br>• Dùng Dialog để tạo/sửa tài nguyên chính thay cho `FormPage` trang riêng; Dialog có `p-0` thiếu `mx-0 mb-0` ở footer; bảng thiếu `onView`/`onEdit`/`onDelete` + `can`, thiếu bulk hoặc `TableBulkBar` không trên 1 dòng; thiếu `useTableState` / `useTabState`.<br>• Dùng thẻ HTML trần (`<img>`, `<a>`, `<button>`, `<input>`, `<select>`), SVG nội tuyến thay vì `public/`, hoặc tiền tố `toannx` trong storage key/cookie/query key/env. |
| 5 | **Phân quyền Ba tầng & Owner** | `51-permissions.md`, `docs/features/permission-scope.md`, `permission-ui.md`, `table-actions.md`, `admin-navigation.md` | • Gộp nhiều model vào 1 file permission; `MEMBER` chứa nhầm `manage_all` hoặc `read_private`; quên `ModuleDescriptor.member_permissions`.<br>• **Bẫy "100% riêng tư" vs `manage_all`**: plan tuyên bố dữ liệu cá nhân tuyệt mật (két sắt, nhật ký riêng) nhưng lại thiết kế theo module chuẩn có `<M>_MANAGER` mang `manage_all` → quản trị viên vẫn xem được nếu không khóa `manage_all` hoặc tách cơ chế.<br>• Bản ghi người khác trả `403` thay `404` (lộ tồn tại IDOR); API kiểm `is_staff`; Menu/View/Table thiếu 3 tầng quyền hoặc ẩn nút thay vì làm mờ + tooltip; option hook bắn 403 ngầm; Portal `/ca-nhan` lẫn vào `ADMIN_MODULE_NAVIGATION` (hoặc ngược lại); module Admin > 5 mục thiếu `section`. |
| 6 | **Bảo mật, Bí mật & Tệp** | `docs/rules/common.md` §5 & §5.2, `30-env-secrets.md`, `53-attachments.md`, `54-security-review.md` | • Tự sinh biến env bí mật cho token nội bộ thay vì dẫn xuất `salted_hmac` từ `DJANGO_SECRET_KEY`; lưu token người dùng vào env thay vì DB qua `SecretCipher`; API trả nguyên secret thay vì masked 4 ký tự cuối.<br>• Chứng từ/hóa đơn/CSV/XLSX/XML để `public` hoặc trả thẳng URL R2 thay vì `visibility="private" lockVisibility` + `/attachments/{id}/content`.<br>• **Bẫy SSRF**: chức năng ping/giám sát URL hoặc lấy metadata cho phép người dùng nhập URL nhưng không qua `validate_public_url` + chặn private IP/loopback/metadata cloud (`169.254.169.254`, `127.0.0.1`, DNS rebinding).<br>• Webhook/Cron thiếu xác thực chữ ký chuẩn (`HMAC` constant-time + replay window, `X-Telegram-Bot-Api-Secret-Token`, `CRON_SECRET`), thiếu rate limit, rò dữ liệu nhạy cảm vào group chat/AI context/log. |
| 7 | **Hạ tầng Free-tier & Hiệu năng** | `docs/architecture/infrastructure.md`, `52-free-tier-infra.md`, `55-performance-review.md` | • **Bẫy đốt Neon 100 CU-giờ/tháng**: cron tick 5–15 phút/lần hoặc polling FE < 5 phút mà **chạm Neon DB mỗi lượt** (mỗi query giữ Neon thức 5 phút → 96 lượt/ngày × 30 ngày = 240 giờ tính thức!). Phải kiểm Redis/lịch đến hạn hoặc đánh giá rõ CU-giờ.<br>• **Bẫy WSGI Streaming / Timeout**: thiết kế SSE streaming dài hoặc ping hàng loạt HTTP tuần tự trong một function `@vercel/python` WSGI mà không xét giới hạn buffering/Active CPU 4 giờ/tháng.<br>• Redis không có TTL, không có fallback khi Redis lỗi/hết hạn mức (gây 500), hoặc dùng Redis cache cho admin/session. |
| 8 | **Thông báo & Dịch vụ Ngoài** | `50-notifications.md`, `docs/features/web-push.md`, `docs/rules/backend.md` §9 | • Plan cho service/cron tự gọi `TelegramClient`/`EmailService`/`FcmClient` trực tiếp thay vì phát qua `NotificationService.notify` + `ModuleDescriptor.notification_events` (nếu có lý do tách riêng kênh chat AI/command bot thì phải nêu rõ phạm vi và ranh giới với hệ thống outbox).<br>• Gửi đồng bộ trong request HTTP; thiếu timeout ≤ 5 giây cho API ngoài (LLM, Telegram, HTTP monitor); thiếu `dedup_key`, `icon`, `details`. |
| 9 | **i18n, URL & Hợp đồng API** | `docs/architecture/i18n.md`, `docs/rules/common.md` §6, `docs/rules/backend.md` §6 | • Quên URL song ngữ `vi`/`en` trong `<M>_PATHNAMES`, quên đăng ký `messages.ts`/`global.d.ts`, quên mã lỗi `<MODULE>_*` + bản dịch `vi`/`en`, quên `journal-field-prefixes.ts`.<br>• Response không theo envelope `{success, data, meta}` (nếu webhook bên thứ ba bắt buộc khác thì phải ghi nhận ngoại lệ rõ ràng như SePay); quên `pnpm api:types` và `spectacular --validate --fail-on-warn`.<br>• Hardcode `.toLocaleString("vi-VN")` hoặc chuỗi tiền/ngày thay vì dùng `shares/lib/number-format.ts`. |
| 10 | **Kế hoạch Kiểm thử** | `11-tests.md`, `docs/rules/backend.md` §12, `docs/rules/frontend.md` §6 | • Gộp nhiều endpoint CRUD vào 1 file test `test_<model>_api.py` hoặc tách `test_<model>_permission.py` riêng.<br>• Thiếu case bắt buộc: `full_data`, `min_data`, `validation_errors`, `401`, `403`, `owner_isolation`, envelope/status, `test_endpoint_access.py`, `test_list_query_count.py`.<br>• FE thiếu test quy ước (`theme-tokens`, `module-structure`, `table-conventions`, `api-contract`, `messages`), thiếu kế hoạch kiểm UI thật `playwright-cli` ở 375px/desktop/light/dark/keyboard/vai trò mẫu. |
| 11 | **Logic Nghiệp vụ & Mâu thuẫn Nội tại** | Chính file plan | • ER diagram ↔ mô tả model ↔ API payload ↔ FE route ↔ Test plan dùng tên model/field/URL khác nhau hoặc mâu thuẫn nhau.<br>• Thiếu edge case: múi giờ UTC (DB/server) vs `Asia/Ho_Chi_Minh` (giờ báo cáo/lịch của người dùng), lặp ngày 29/30/31 hàng tháng, chuyển đổi nhiều ngoại tệ khi cộng tổng, race condition cron chạy đè nhau, mất/quá hạn token AI, giới hạn kích thước lịch sử chat/context. |
